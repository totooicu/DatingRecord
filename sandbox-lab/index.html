沙盒试验台 · 批量修改指令

几篇初始文章 + 一堆修改指令，验证四个动作：预览（纯算不写回）、执行（提交成新版本）、放弃（丢指令不动内容）、恢复（回到旧版本 / 找回已放弃）。

修改指令

沙盒模型：为什么预览必须是纯函数

沙盒里只有两份真相：docs（已提交的文章）与 instructions（指令队列 + 每条的状态）。 pass(docs, ids) 在 docs 的深拷贝上按队列顺序跑一遍，返回「新内容 + 每条指令的成败 + 逐篇差异」， 全程不碰 docs，所以预览可以随便点、反复点。

指令互相喂：i6 要改的「小柚」是 i5 造出来的，所以不能缓存单条结果， 也不能并行跑——预览必须整条流水线重算。单条预览只是给孤立结果，放进队列重算才算数。

跑不通的指令（原文找不到、目标文章不存在、内容已经是这样）整条拒绝，进「需复核」并留原因， 绝不部分写入。批量执行时成功的照常提交、失败的留在队列，不因为一条坏指令把整批卡死。

四个动作都不销毁历史：执行 落一个新快照；放弃 只改指令状态，内容一个字节没动； 恢复 把当前现场也存成快照再切回去，所以回滚本身还能再回滚；找回 把已放弃的指令放回队列。

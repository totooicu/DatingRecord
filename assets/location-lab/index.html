      结论—

        壳在取证模式下每秒写一行账：tick=真发了一次定位请求，skip=这一拍上一发还没回所以没发（也算进程活着）， fix=取到点并带当时经纬度，fail=失败/超时/唤醒锁被收走，screen=灭屏亮屏解锁， start / stop=采集起来或被停（带是谁按的：page=页面推的配置、system-restart=系统重建后恢复），destroy / taskRemoved=服务被销毁、任务被划掉。 判读口径：每拍都在且 fix 不断 → 壳没睡；大空档前面正好有一行 stop → 不是睡，是被停了（十有八九是页面把「自动打点」关了）； 空档落在灭屏期间 → 熄屏后被冻；亮屏时也停、还报「没持唤醒锁」 → 壳自己没把锁拿到手； 空档只有 3~4 秒 → 取证节拍的抖动，标「抖动」不标冻结； 拍连着但没有 fix → 醒着却拿不到定位（多半没给「始终允许」，或省电把 provider 掐了）。 空档下面那行小字是壳自己的物证：开机钟 ≈ 墙钟 = 手机醒着、只有壳被冻；开机钟少走一大截 = 整机深睡；Doze / 省电模式 / GPS 被关 是环境原因；闹钟 N/M 是 60 秒心跳的对照—— 一次都没进来就是被冻或被杀，进来了而拍没跟上就是线程问题。

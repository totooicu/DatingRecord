# 沙盒接入手册（AI 操作事务内核）

目录：`ai-sandbox/`。这份手册面向**要在沙盒之上继续开发的人**（宿主 UI、Agent 编排层、后续把 AI 真接进来的那位）。
读完能回答三个问题：指令长什么样、沙盒会拦什么、拦下之后宿主该怎么演。

先看文件：

| 文件 | 作用 |
| --- | --- |
| `core.mjs` | 内核，纯 ESM、零依赖、不碰 DOM（994 行）。Node 和浏览器都能直接 `import` |
| `selfcheck.mjs` | 内核自检，269 条断言，`node ai-sandbox/selfcheck.mjs` |
| `lab-app.js` | 实验台 UI 源码（示例世界 + 指令池 + 四个按钮） |
| `build-lab.mjs` | 把内核 + UI 内联成单文件 `lab.html`，`node ai-sandbox/build-lab.mjs` |
| `lab.html` | 生成产物，手机上双击就能玩；不要手改，改 `lab-app.js` 重新生成 |
| `lab-e2e.mjs` | 浏览器回归，`node ai-sandbox/lab-e2e.mjs`（需 Playwright + Chromium） |

跑一遍全套：

```bash
node ai-sandbox/selfcheck.mjs      # 内核 269 断言
node ai-sandbox/build-lab.mjs      # 生成 lab.html
node ai-sandbox/lab-e2e.mjs        # 浏览器 56 断言（file:// 直开）
```

## 0. 心智模型：四个名词

```
state      已提交的世界状态（一棵 JSON 树）
op         一条声明式指令（只有数据，没有代码）
changeset  一批 op 的草稿：begin → dispatch* → dryRun → commit | discard
journal    版本流水：commit 与 revert 都只追加，永不删除
```

前提假设：**AI 是一个会递过来任何 JSON 的实习生**。它可能写错类型、改到不该改的路径、塞一段脚本、删掉被引用的实体、一次改五千个字段、或者同一批指令两次算出两个结果。
沙盒的职责不是让 AI 别犯错，而是**让犯错的指令进不了状态**。

三条不可谈判的规矩：

1. 指令只能是数据。`kind: 'script' / 'eval' / 'sql' / 'html' …` 一律拒绝，不给降级执行的余地。
2. 预览不改状态、不外发。副作用只在 `commit` 成功后写进 `sink`。
3. 执行要么整批过，要么明确知道自己过了几条（`acceptPartial`）。没有「悄悄改了一半」。

## 1. 三十秒上手

```js
import { createSandbox } from './core.mjs';

const sb = createSandbox({
  world:  { docs: { a1: { id: 'a1', title: '旧标题', tags: ['徒步'] } }, settings: { theme: 'auto' } },
  schema: [
    { path: 'docs', entity: { id: { type: 'string' }, title: { type: 'string', min: 1, max: 40 }, tags: { type: 'array', items: 'string', maxItems: 6 } } },
    { path: 'docs.*.title', type: 'string', min: 1, max: 40 },
    { path: 'docs.*.tags', type: 'array', items: 'string', maxItems: 6 },
    { path: 'settings.theme', type: 'string', enum: ['auto', 'light', 'dark'] },
  ],
  effects: { notify: { describe: '发一条提醒', compensate: 'cancel-notify' } },
  env:     { weather: '晴' },        // 外部只读快照
  policy:  { mode: 'atomic' },       // 缺省即 DEFAULT_POLICY
});

sb.begin('AI 的第一批', { seed: '42', clockISO: '2026-10-27T09:12:00.000Z', env: sb.getEnv() });
sb.dispatch({ kind: 'set', path: 'docs.a1.title', value: '西湖徒步路线笔记' });
sb.dispatch({ kind: 'effect', name: 'notify', args: { text: '改好了' } });

const pv = sb.dryRun();            // 只算，不改
if (pv.ok) {
  const c = sb.commit();           // { ok, version, changed, effects, partial, failed }
  // 副作用这时候才进 sb.sink
} else {
  sb.discard();                    // 把问题丢回给 AI 重写
}
```

宿主侧真正要写的只有两件事：**把 `pv.changes` 渲染成人能看的 diff**，**把 `pv.problems` 连 `fix` 一起回喂给 AI**。

## 2. 指令协议

所有指令共同字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 建议必填。出问题时报 `opId`，UI 和回喂 AI 都靠它定位；缺省自动编号 `op1/op2…` |
| `expect` | 前值断言（可选）。当前值与 `expect` 不等 → `conflict`。用于「AI 基于旧版本发的指令」 |

### 2.1 八种 kind

```jsonc
// set —— 覆盖写。路径必须已存在或父节点存在，否则 no-target / unknown-path
{ "kind": "set", "path": "docs.a1.title", "value": "新标题", "expect": "旧标题" }

// delete —— 删除。被引用且没 cascade → dangling
{ "kind": "delete", "path": "docs.a3", "cascade": false }

// insert —— 往数组插一项。path 指向数组本身；index 缺省追加，越界自动夹到端点
{ "kind": "insert", "path": "docs.a1.tags", "value": "西湖", "index": 0 }

// reorder —— 数组内挪位。from/to 越界 → bad-index
{ "kind": "reorder", "path": "tripLog.days", "from": 1, "to": 0 }

// rename —— 改对象的键名（不改值）。path 指旧键；to 不能含 . 或双下划线或保护区名
{ "kind": "rename", "path": "docs.a1", "to": "b7" }

// create —— 新建实体。at 指向集合；字段必须在 entity 表里声明过
{ "kind": "create", "at": "docs", "value": { "title": "雨天备选", "tags": ["备选"] }, "id2": "a9" }

// effect —— 外部动作。必须先在 effects 登记；预览只登记，执行才外发
{ "kind": "effect", "name": "notify", "args": { "text": "行程已更新" } }

// bulk —— 把多条打包成一条（AI 很爱用）。展开后计入 maxOps，展开 id 形如 b1#0、b1#1#0
{ "kind": "bulk", "ops": [ { "kind": "set", "path": "settings.theme", "value": "dark" } ] }
```

`create` 的细节：`at` 指向**对象表**（`docs`）时按 id 建键，`id2` / `value.id` 缺省时用种子派生；指向**数组**（`tripLog.days`）时按下标追加，不强塞 `id`（除非 entity 表声明了 `id` 或值里本来就有）。

### 2.2 令牌：把非确定值变成可重放值

写在 `value` / `args` 的字符串里：

| 令牌 | 展开为 | 由什么决定 |
| --- | --- | --- |
| `{{now}}` | 本批 `clockISO` | `begin({clockISO})` |
| `{{uuid}}` | `x` + base36 | 种子 + 路径 |
| `{{random}}` | 0–1 六位小数 | 种子 + 路径 |
| `{{env:KEY}}` | 外部快照里的值 | `begin({env})` 的那份快照 |
| 其它 `{{xxx}}` | 原样保留 | 记 note `token-unknown` |

派生公式：`seedText = '#' + 版本数 + '#seed=' + seed`。**批次名称不参与**，所以给人看的名字随便改，数据不变。
含义：同一份指令、同一个 seed、同一个 clockISO，重放 100 次得到逐字相同的结果 —— 预览和执行不可能出现两个版本。
`{{env:*}}` 是唯一的例外，见 §7。

### 2.3 明确禁止的东西

| 形态 | 结果 |
| --- | --- |
| `kind` 属于 `script/function/js/javascript/eval/import/require/raw-sql/sql/shell/bash/command/exec/html/dom/fetch` | `not-declarative` |
| 指令对象上出现 `__proto__` / `constructor` / `prototype` 自有键 | 键被**静默丢弃**，预览留 note `proto-keys`，其余字段照常执行 |
| 字段值是函数 / Symbol / undefined | 整条作废 `not-declarative`（因为 `JSON.stringify` 会静默吞掉，不能假装没事） |
| 路径段命中 `sandbox/__proto__/constructor/prototype/secrets/keys/ledger/env`，或任何段含 `__` | `protected` |
| 值嵌套超 24 层 / 循环引用 | 被截断成 `'[深度超限，已截断]'` / `'[循环引用，已截断]'` |
| `bulk` 自引用、超深、`ops` 不是数组 | `not-declarative` |

> 注意最后一条保护名单里的 `env`、`keys`、`sandbox` 是**段名**匹配。宿主世界里的字段别起这些名字，否则指令永远改不动（这是有意的：宁可误伤也不留缝）。

## 3. Schema 规则

一条规则 = 一个路径模式 + 约束。`*` 匹配一段，`**` 匹配剩余任意段（含零段）。**取最长匹配**；长度并列时先声明的赢。

```js
{ path: 'docs.*.title', type: 'string', min: 1, max: 40 }
```

| 字段 | 适用 | 含义 |
| --- | --- | --- |
| `type` | 全部 | `string / number / boolean / array / object / date / hex / any`。`date` = `YYYY-MM-DD` 前缀；`hex` = `#rrggbb` |
| `min` / `max` | string 长度、number 取值 | 双语义，别混在一条规则里 |
| `enum` | 标量 | 允许值列表 |
| `items` | array | 元素类型名（`string/number/...`），配合 `itemEnum` / `itemMax` |
| `maxItems` / `minItems` | array | 元素个数 |
| `ref` | 标量或数组 | 指向集合路径，如 `'docs'`；数组会逐元素查池 |
| `required` | 任意 | 缺省或 null 时报 `bad-value`（仅 entity 表内生效） |
| `entity` | 集合 | `{ 字段: 规则 }`，`create` 的合法性来源 |

两条容易踩的：

1. **校验是递归的，不是只查叶子。** 整对象写入时，容器层的 `maxItems` / `enum` / 区间 / `ref` 都会查，然后逐子节点继续。所以给 `docs.*.tags` 写 `maxItems: 6` 真的会拦 7 个标签。
2. **`ref` 的池子按 `path` 找。** `ref: 'docs'` 表示去 `state.docs` 找：对象表看键，数组看 `id` 字段。
3. **规则要写全。** 没规则约束的叶子在 `strict` 下是 `unknown-path`。给 `settings.*` 兜一条 `type:'any'` 之前，任何新字段都进不来。

## 4. 策略开关（`policy`）

```js
{ mode:'atomic', unknownPath:'strict', maxOps:200, maxBytes:65536, maxChanges:400, maxDepth:12, allowCreateEntity:true }
```

| 键 | 作用 | 调它的时机 |
| --- | --- | --- |
| `mode` | `atomic` 一条不过整批不进；`lenient` 跳过坏条继续算 | 交互式让用户选；后台批量任务用 `atomic` |
| `unknownPath` | `strict` 拒绝未声明路径；`open` 放行并记 note | 迁移期放宽，稳定后收紧 |
| `maxOps` | 单批指令数（bulk 展开后计） | AI 一次改 300 个字段就在这里断 |
| `maxBytes` | 单条写入值的字节数（UTF-8） | 防 20 万字正文灌进来 |
| `maxChanges` | 单批影响字段数 | 防「一条指令改天换地」 |
| `maxDepth` | 路径段数上限 | 防 `a.b.c.…` 无限套娃 |
| `allowCreateEntity` | 关掉后 `create` 一律 `policy` | 只允许编辑、不允许新增的场景 |

`sb.policy` 是活对象，UI 上直接改就行（实验台就是这么做的）；但**改完要重新 `dryRun`**，判定发生在算的时候。

## 5. 一趟批次的生命周期

```
begin(name, {seed, clockISO, mode, env})   开草稿批
  dispatch(op) * n                          只入队，不校验
dryRun()                                    完整算一趟，返回 res（不改状态）
commit(opts)                                再算两趟核对，才落状态
discard()                                   丢掉草稿，返回条数
```

`dryRun()` 返回的 `res`：

| 字段 | 含义 |
| --- | --- |
| `ok` | 整批能不能放行（宽松模式有跳过就是 `false`） |
| `aborted` | 是否被中止（原子撞坏条 / 超限额） |
| `changes[]` | `{path, kind:'add'|'mod'|'del', before, after, via, opId}` —— **预览就渲染它** |
| `problems[]` | `{opId, code, msg, fix}` —— 原子模式下的拦截；**回喂 AI 就靠它** |
| `failed[]` | 宽松模式下被跳过的坏条（同结构）。原子模式恒为空，避免同一问题数两遍 |
| `notes[]` | 提示（不算错，但要知道）：`token / env-read / env-missing / token-unknown / cascade / created / effect / proto-keys / open-create` |
| `effects[]` | 本批副作用（含 `irreversible` / `compensate`），预览阶段不外发 |
| `applied / skipped / ops` | 计数。原子中止时 `applied` 是「中止前算过几条」，不代表落地 |
| `result` | 预览后的世界。`aborted` 时**就是原状态**（不给你看半截世界） |
| `flat` | 展开后的指令数组（`commit` 拿它复算，别改它） |
| `envDeps[]` | 本批读过哪些外部键 |

`commit({acceptPartial})` 的门槛顺序（不可换）：

1. **两趟预览逐字相同** → 否则 `unstable`（AI 混进真随机/依赖顺序就在这里露馅）
2. `res.ok`；或宽松模式下 `applied>0 && skipped>0` 且 `acceptPartial:true` → 否则 `blocked`
3. 外部快照未漂移 → 否则 `env-drift`
4. **第三趟独立复算**必须复现预览结果 → 否则 `unstable`
5. 全空批次（无改动无副作用）→ `{ok:true, noop:true}`，不留版本
6. 追加版本 → 落状态 → **这时候**才把副作用写进 `sink`

> `res` 里所有东西都是克隆，随便读；但别指望改 `res.result` 能影响沙盒 —— 状态只能通过 `commit` 变。

## 6. 回退与补偿

```js
sb.lastApplied()                 // {seq,label,kind} | null —— 最近一次还没被回退的执行
sb.revert()                      // 默认退 lastApplied
sb.revert({ seq: 7 })            // 显式指定；seq 指向 revert 记录 = 重做那一版
sb.revert({ seq: 7, force: true })
```

规则：

- 回退**只追加**新版本（`kind:'revert'` / `'redo'`），旧记录打上 `reverted`，永不删除。
- 默认只退「最近一次未被回退的执行」，所以可以连着往前拆好几版。
- 退一条 `revert` 记录 = 重做（`redo`），且必须是最新一条，否则 `not-lifo`。
- 已回退过的版本再退 → `already-reverted`（提示你去退那条回退记录）。
- **双轨自检**：先按 `undo` 逆序重放，再和上一版快照比（忽略键序）。不一致 → `undo-mismatch` 拒绝回退。这条是内核自查，说明内核自己记错了账，宁可不动也不覆盖真实状态。
- 落地时**以快照为准**，`undo` 只用于自检。
- 副作用不回滚，只补偿，写进 `sink`：

| 副作用声明 | 回退时 sink 的 `type` |
| --- | --- |
| 有 `compensate` | `compensate`（带补偿动作名，宿主去执行） |
| `irreversible: true` | `manual`（转人工；默认**拒绝回退**，`force:true` 才放行） |
| 都没有 | `withdraw`（尽力撤回） |

宿主必须有一个消费 `sb.sink` 的地方 —— `sink` 是 `{type, name, args, version}` 的追加数组，**沙盒不执行任何东西**。

## 7. 外部值（env）与漂移

`{{env:KEY}}` 读的是 `begin({env})` 那份快照，同时把 KEY 记进 `res.envDeps`。
`commit` 前会比对 `cfg.env` 现值与快照：变了就 `env-drift` 整批拒绝，**不会**用新值悄悄重算。

为什么要这么硬：预览给用户看的是「两天，三个地方，晴 天」，执行时天气变成暴雨还照样落库，就是当着人的面撒谎。
正确姿势：宿主在每次 `begin` 时传当前 env；外部值变了就重新打包预览。

## 8. 问题码总表

| code | 触发 | 宿主建议动作 |
| --- | --- | --- |
| `not-declarative` | 禁 kind / 函数值 / bulk 展开失败 | 原样回喂 AI，让它改成数据操作 |
| `bad-kind` | kind 不在八种里 | 同上 |
| `bad-shape` | 内核内部抛错（兜底） | 记日志 + 补自检用例 |
| `protected` | 路径或新名字命中保护区 | 告诉用户「AI 想改不该改的东西」，别自动重试 |
| `bad-path` | 路径空 / 超深 / 中段不是容器 | 回喂 |
| `bad-value` | 类型、长度、枚举、数组项、id 非法、缺 value | 回喂，带 `fix` |
| `bad-ref` | 引用了不存在的实体 | 让 AI 先建实体或换 id |
| `no-target` | 要改/删的东西不存在，或 set 想凭空造实体 | 引导改用 `create` |
| `conflict` | `expect` 前值断言不匹配 | **必须重新预览**，别让 AI 直接重发 |
| `unknown-path` | strict 下 schema 没写的路径 | 补规则或回喂 |
| `oversize` | 单条写入超 `maxBytes` | 让 AI 拆条 / 只给增量 |
| `dangling` | 删除会留下悬挂引用 | 问用户要不要 `cascade` |
| `bad-index` | insert/reorder 下标越界 | 回喂 |
| `dup-id` | create 撞 id / rename 目标名已存在 | 回喂 |
| `unknown-effect` | 副作用没登记 | 回喂，或宿主先 `registerEffect` |
| `policy` | 策略禁止（如关了 create） | 提示改策略或换指令 |
| `too-many-ops` / `too-many-changes` | 超批量/影响面限额 | 让 AI 分批 |
| `no-batch` | 没 `begin` 就 `dispatch/dryRun/commit` | 宿主代码 bug |
| `unstable` | 两趟预览不一致 / 复算与预览不一致 | 别重试，把 `detail` 打出来排查 |
| `blocked` | commit 时仍有问题 | 展示问题列表 |
| `env-drift` | 外部值在执行前变了 | 重新打包 |
| `not-lifo` | 想退的不是最新执行 | 按顺序退 |
| `irreversible` | 含不可逆副作用的版本要回退 | 走人工，确认后再 `force` |
| `undo-mismatch` | 内核自检发现账对不上 | 立即停止回退，上报 |
| `no-version` / `already-reverted` | 没有可退的执行 / 退过了 | 刷新流水 |

`fix` 字段是给人看的「怎么改」，也是给 AI 的下一轮提示词素材 —— 别丢掉。

## 9. 宿主接入清单（以 DatingRecord 为例）

本项目现状：React + Vite + sql.js(WASM SQLite) + Leaflet，PWA，数据在 IndexedDB/SQLite 里。
沙盒**不接管持久层**，它管「AI 提议的改动能不能落地」这一段。落地仍走现有仓库层。

1. **定义世界。** 把要交给 AI 改的那部分摊成 JSON 树：
   ```js
   { docs: { <id>: {id,title,body,tags,color,updatedAt,pinned} },
     tripLog: { days: [{date,title,docIds}], note },
     settings: { theme, fontSize } }
   ```
   键名避开保护区词（`env/keys/ledger/sandbox/...`）。
2. **写 schema。** 每条实体集合给一份 `entity` 表 + 逐字段规则 + 引用规则（`docIds → docs`）。漏写的字段在 strict 下进不来。
3. **登记副作用。** 提醒、同步日历、发短信这类外部动作，先声明 `compensate` 或 `irreversible`。没登记的名字一律 `unknown-effect`。
4. **接 sink。** 在宿主里挂一个消费循环（`type` 分发到真实 API；`compensate` 调撤销接口；`manual` 弹人工确认）。
5. **UI 三件套。** 预览面板（`changes` 按 add/del/mod 分组）、拦截面板（`problems + failed`）、流水面板（`journal()`）。四个动作对应 `pack/preview/execute/revert`，见 `lab-app.js`。
6. **持久化。** 建议把 `versions`（去掉 `snapshot` 也可以，用 `ops` 重放）和 `sink` 一起存，重启后 `createSandbox({ world: 最新快照, ... })` 再灌回流水。
7. **AI 侧提示词。** 把 §2 的协议和 §3 的规则表塞进系统提示，并明确「只准输出 JSON 指令数组，输出别的都会被拒」。
8. **失败回喂。** `problems[].fix` 拼成第二轮 prompt 的主体。原子模式下整批退回，让 AI 重发；宽松模式下只把坏条回喂。
9. **限额按场景调。** 移动端批量整理用默认值；导入迁移场景临时抬 `maxOps/maxChanges`，并强制 `atomic`。

## 10. 怎么加自检用例

打开 `selfcheck.mjs`，抄现有分组的样子：

```js
group('N 我新想到的敌意形态');
{
  const { s, r } = run([{ id: 'n1', kind: 'set', path: 'docs.a1.title', value: 'x' }]);
  ok(has(r, 'bad-value'), 'N1 一句话说明这条在防什么', r.problems);
}
```

- `sb(extra)` 拿全新沙盒；`run(ops, opts)` = 建沙盒 + begin + dispatchAll + dryRun。
- `codes(r)` / `has(r, code)` / `first(r, code)` 已经兼顾 `problems` 与 `failed`。
- 比较状态一律用 `sameState`（忽略键序），别 `JSON.stringify` 直接比 —— `rename` 重放会改键序。
- 加完跑 `node ai-sandbox/selfcheck.mjs`，最后一行必须是 `沙盒内核自检全绿。`
- 内核改了行为，`lab-e2e.mjs` 里的断言也要跟着改；两边都绿再提交。

## 11. 坑清单（都真踩过）

1. **规则取最长匹配。** 先写 `settings.*`（`any`）再写 `settings.theme`（enum）不会有问题，但反过来靠的是最长匹配，不是顺序；并列长度才看声明顺序。
2. **别只校验叶子。** 容器层的 `maxItems` / `ref` / 区间必须查，否则 7 个标签照样进。
3. **比较状态要忽略键序。** `canon()` / `sameState()` 是为此存在的。
4. **`safeValue` 有深度上限（24）**，超了变字符串。别在展开阶段假设 `op.ops` 一定是数组。
5. **`res` / `res.flat` 是克隆**，改它不影响沙盒；但**别改**，`commit` 会拿 `flat` 复算，改了就 `unstable`。
6. **原子模式的 `applied>0` 不代表落地**，`result` 才是真相（中止时等于原状态）。
7. **`set` 不能凭空造实体**（`no-target`），要新建用 `create`。
8. **纯副作用批次也会生成版本**（状态没动但有账），别按「状态没变」把它当 noop 吞掉。
9. **`file://` 下 ES Module 会被 CORS 拦**，所以 `lab.html` 必须内联全部 JS —— 这就是 `build-lab.mjs` 存在的原因。
10. **克隆别用 `JSON.parse(JSON.stringify())` 处理 AI 输入**：函数会被静默丢掉，`__proto__` 键会污染原型。内核用的是手写 `safeValue`。
11. **保护区是段名匹配**，宿主字段起名避开 `env/keys/ledger/sandbox/secrets`。
12. **`begin` 不传 `clockISO` 会退到 1970**（`new Date(0)`）—— 这是故意的（不传就没有真时间），宿主必须显式传。

## 12. API 速查

```js
// 批次
begin(name, {seed, clockISO, mode, env})   dispatch(op) → {ok,index,id}   dispatchAll(ops)
dryRun() → res    checkDeterminism() → {stable, first, second}
commit({acceptPartial}) → {ok,version,changed,effects,partial,failed,noop?,code?,msg?}
discard() → n     pending() → ops[]        batchInfo() → {...} | null

// 状态与流水
state() → 克隆    head() → 最新版本        versionAt(seq)                snapshotOf(seq)
journal() → [{seq,label,kind,changed,skipped,reverted,effects,at,undo,ops}]
lastApplied() → {seq,label,kind} | null
revert({seq?,force?,at?}) → {ok,version,backTo,redo} | {ok:false,code,msg}

// 配置与外部
policy（活对象）  schema()  ruleFor(path)  setMode(m)  setEnv(k,v)  getEnv(k?)
registerEffect(name, {describe, compensate, irreversible})   effects() → [{name,irreversible,compensate}]
sink（追加数组，宿主自己消费）   versions（只追加，别改）

// 独立工具（可单独 import 做 UI）
createSandbox, diffTrees(a,b), classify(changes), canon, sameState, leaves,
parsePath, joinPath, getAt, truncate, bytes, clone, isPlain,
matchPattern, ruleFor, checkScalar, hashRnd, resolveTokens,
PROTECTED_SEGMENTS, OP_KINDS, FORBIDDEN_KINDS, DEFAULT_POLICY
```

`diffTrees` + `classify` 是给你做「只列增/删/改」式预览的捷径：`classify(diffTrees(res.before, res.result))` 得到与 `res.changes` 同类的清单，适合按文章聚合展示（实验台用的是 `res.changes`，因为要精确到字段）。

## 13. 现在还没做的

- 内核不认「语义」：`docs.a1.body = '密钥是 sk-live-abcdef'` 这种把秘密**抄进合法字段**的指令会放行。要防得住，得在宿主侧加内容扫描（正则/熵检测）再包一层。
- `sink` 只是数组，没有重试、幂等、失败回滚；宿主接真实 API 时要自己加。
- 没有跨沙盒事务（两个沙盒同时改一份数据）；单进程单实例模型。
- 快照全量存，版本多了会胖；真要上线需要改成增量 + 定期压实。
- `notesProto` 是共享数组（`normalizeOp` 往里塞、`protoNotes()` 抽干），单线程够用，将来上 worker 并发要先改成按趟传参。

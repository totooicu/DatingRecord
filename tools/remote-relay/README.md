# 跨设备操作中继（remote-relay）

浏览器页面不能监听 TCP 端口，所以「跨设备操作」的服务端需要这个小进程转发 WebSocket 消息。
它**不碰数据库**：数据始终在服务端那个浏览器标签页里，中继只转发整库快照和附件字节。

中继是可选的：页面里选「直连（WebRTC）」时，两个浏览器交换邀请码 / 应答码后直接建立
DataChannel，不经过任何服务器（STUN 只用来发现公网地址，不转发数据）。适合同一局域网、
两边都能打开同一个 `https` 页面、或网络允许 P2P 的情况；网络限制严格时仍建议用中继。

## 入口

```bash
node tools/remote-relay/server.mjs --port 4173 --token mytoken
# 或
npm run relay -- --port 4173 --token mytoken
```

参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--port` | `4173` | 主监听端口；页面里的「端口号」与它一致时可直接开启 |
| `--token` | 随机 10 位 | 访问 token；页面里点「开启跨设备操作」时可以用页面上的 token 覆盖 |
| `--host` | `0.0.0.0` | 监听地址；只给本机用可填 `127.0.0.1` |
| `--dist` | `dist` | 静态构建产物目录；先 `npm run build` |

## 怎么用

1. 在放数据的电脑上 `npm run build && npm run relay -- --port 4173 --token abc123`。
2. 电脑打开 `http://127.0.0.1:4173/`，进「设置 → 备份与分享 → 跨设备操作」：
   - **作为服务端**：端口 4173、token abc123，点「开启跨设备操作」。
   - 页面会显示客户端连接串（`本机IP:4173?token=abc123`）。
3. 手机/另一台电脑打开 `http://本机IP:4173/`（必须由中继托管，`https` 页面连不上 `ws://`）：
   - **作为客户端**：填上面的连接串，点「连接服务端」。
4. 客户端此后读写的是服务端的数据；断开后自动回到自己的本机数据。

## 直连（WebRTC，不用中继）

1. 两台设备都打开同一个页面（推荐 `https` 部署，或都在同一局域网）。
2. 服务端在「跨设备操作」里切到「直连（WebRTC）」，点「生成邀请码」。
3. 把 `DR1H:` 开头的邀请码发给另一台设备；对方在同一页切到直连，粘贴后点「生成应答码」。
4. 把 `DR1A:` 开头的应答码发回服务端，服务端点「完成配对」。
5. 配对成功后数据仍然是「服务端整库 + 客户端只读转发写入」，与中继模式一致；
   任何一边关闭页面或断网，客户端都会立刻回到本地数据。

手动转发邀请码 / 应答码就是信令，页面不请求任何第三方服务器。留空 STUN 只走局域网；
跨网络时填 `stun:stun.l.google.com:19302` 之类，但 STUN 只帮助打洞，不转发数据。
企业网络 / 对称 NAT 下打洞可能失败，此时请改用中继。

## 协议（两层）

- 中继层：`{t:'hello'|'to'|'broadcast'}`；连接先发 `hello` 登记 `host` / `client`，中继分配 id，
  转发时附 `from`，所以服务端能区分是哪个客户端发来的。
- 业务层（浏览器之间）：`snapshot` / `apply` / `blob-*`。写操作是「整库快照 + baseVersion」，
  版本冲突时中继不合并，直接把服务端最新快照发回给那个客户端（避免互相覆盖）。

### /__remote/info（诊断用）

`GET /__remote/info[?token=xxx]` 返回 `{ok, port, hostOnline, clients, tokenOk, addresses}`，
带 `Access-Control-Allow-Origin: *`，好让客户端页面在连接前先分清楚「中继不在 / token 不对 /
服务端没开」，而不是一律报「连不上中继」。`tokenOk` 只在请求带了 `token` 时返回。

## 已知限制

- 明文 `ws://`，只适合可信局域网；没有 TLS。
- 单服务端；第二个 `host` 会被拒绝。
- 端口上已有服务端在线时不能再改 token（否则等于把它静默踢下线），要换请先停掉原来的服务端。
- 写冲突用「后写者收到最新快照、本次改动不覆盖」的策略，不做字段级合并。
- 服务端标签页关闭后，客户端会被中继断开并自动回到本地数据。
- 纯静态托管（GitHub Pages）上没有 `/__remote/listen`，页面只能连已经启动的中继端口；
  浏览器也不能自己监听端口。
